# novel-classify —— 本地批量小说风格归类

上万个 txt、单本几十 MB，按题材（武侠/仙侠/玄幻/都市/科幻/历史/言情/游戏/末世/灵异）
快速归类。**不联网、不调用 LLM、不上传任何正文**，只用 Python 标准库（无第三方依赖）。

## 为什么不用上传全文

题材是**词频分布特征**，不是语义推理任务。一本书里「江湖/内力/掌门」和「手机/总裁/地铁」
的相对密度，抽 500 KB 就已经稳定，几十 MB 的全文带来的额外信息几乎为零。

所以流程是：**每本只读 4 段、共 500 KB → 算特征 → 本地打分 → 出 CSV**。
一万本 × 20 MB 的书库（200 GB），实际只读约 5 GB，CPU 时间约 2~3 分钟（4 核）。

## 快速开始

```bash
# 1) 零样本，直接归类（内置 10 类词表 + 整批 z 分数自校准）
python3 novel_classify.py /volume1/novels --out 归类.csv --jobs 4

# 2) 先小规模试跑，看低置信比例再上全量
python3 novel_classify.py /volume1/novels --limit 300 --out 试跑.csv

# 3) 想更准：每类挑 15~30 本已确认题材的书，按目录名放好，训练质心模型
#    seeds/武侠/*.txt  seeds/仙侠修真/*.txt  seeds/都市/*.txt ...
python3 novel_classify.py --train ./seeds --model-out model.json
python3 novel_classify.py /volume1/novels --model model.json --out 归类.csv

# 4) 顺手查重复转载的书（出版社/网站重复收录很常见）
python3 novel_classify.py /volume1/novels --simhash --out 归类.csv
```

输出 CSV（UTF-8 BOM，Excel 直接打开）：

| 列 | 含义 |
|---|---|
| `path` | 文件路径 |
| `size_mb` / `read_mb` | 文件大小 / 实际抽样读了多少 MB |
| `encoding` | 识别出的编码（utf-8 / gb18030 / big5 / utf-16） |
| `chars` | 抽样里有多少汉字 |
| `label` | 判定题材 |
| `confidence` | 把握度（校准时为 logistic 值，否则为得分占比） |
| `second` / `margin` | 次选题材 / 与次选的差距 |
| `low_conf` | `yes` = 需人工或 LLM 复核 |
| `hint` | 文件名里带的题材提示 |
| `evidence` | 判定依据（命中的特征词及次数，人工一眼能验） |
| `s_*` | 各题材原始得分 |
| `simhash` | 近似重复指纹（`--simhash`） |

## 两条判定路径

**零样本（内置词表）**：题材专指词加权命中密度，先按段打分再取中位数，
最后在整批语料上做 z 分数自校准。适合「现在就想跑一遍看看」。

**质心模型（有标注时）**：字符 bigram 的 TF-IDF 质心余弦（Rocchio）。
用相对词频而非计数（长短书可比），idf 用 `log(类数/df)`，让所有题材都高频的
通用 bigram 权重归零。每类 15 本起，30 本更稳。**这是准确率明显更高的路径。**

## 实测数据（本机 4 核 / 7 GB，合成语料，热缓存）

| 场景 | 速度 | 说明 |
|---|---|---|
| 1200 文件 / 2.0 GB，500 KB 抽样，4 进程 | **67.6 本/秒**，18 秒 | 实读 566 MB（27.7%） |
| 同上，100 KB 抽样 | **313 本/秒** | 判定结果与 500 KB 一致 |
| 单进程 500 KB | 21 本/秒 | 线性扩展约 3.2× |
| 1 万本外推（500 KB / 4 进程） | **约 2.5 分钟** | CPU 密集，I/O 只占 5 GB |

合成语料上词表路径与质心路径都是 100%，**但这只证明管道正确，不证明真实准确率**——
真实书上预期：词表路径大类 80~90%，质心路径 90%+，具体取决于你的书库和分类粒度。

已处理并测过的坑：

- **GBK/GB18030**：中文小说约三成是 GBK。按严格解码判断编码，60/60 全部识别正确；
  按字节切样本会把汉字切两半，这个边界已专门处理（否则约 2/3 的文件会被误判）。
- **前言/目录/盗版广告污染**：一段 600 KB 纯都市词的前言曾让武侠书被判成都市。
  改为「4 段各自打分取中位数」后，单段污染翻不了盘。
- **非小说文本**：技术文档、纯英文、空文件不会硬判。加了绝对证据量门槛
  （命中权重 < 12 或只有 1 个词种 → `未分类` + 低置信），实测那几份中文 md
  全部落到 `未分类`/低置信，没有出现「100% 把握判成都市」。
- **重复转载**：`--simhash` 出 64 位指纹，汉明距离 ≤ 3 基本是同一本书。

## 已知局限（都建议用 `low_conf` 兜住）

1. **题材边界本来就模糊**：武侠 / 仙侠 / 玄幻 三者交叉严重（「武侠修真」「都市异能」
   「玄幻武侠」都是真实品类）。单标签必然丢信息——把 `second` 一起看，或直接按
   `low_conf` 复核，别指望 100%。
2. **子类型要靠模型**：内置词表只有 10 个粗类；你想要「克苏鲁/无限流/种田文」这类
   细分，只能走 `--train`（词表跟你的类别名不对应时，程序会自动关掉词表相关的门槛）。
3. **词表是软先验不是真理**：作者用词偏离通用词表时会掉分，这正是质心模型存在的理由。
4. **抽样看不到极端结构**：整本都是对话体、或正文只占 1% 的「合集包」可能判偏，
   这类会掉进 `low_conf`。

## 和 LLM 怎么分工

只对 `low_conf=yes` 的那部分（经验上 5~15%）用 LLM 复核，而且**只发 2 KB 摘要**
（开头 1 KB + 中段 1 KB），不是全篇：

- 1 万本全量过 LLM：约 200 GB 文本，不可行；
- 1 万本 × 10% = 1000 本 × 2 KB = 2 MB，一次批量调用就够，成本可忽略。

```bash
# 从结果里挑出需要复核的
python3 -c "
import csv
rows=[r for r in csv.DictReader(open('归类.csv',encoding='utf-8-sig')) if r['low_conf']=='yes']
print(len(rows),'本待复核')
"
```
